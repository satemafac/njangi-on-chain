# Soft-launch gameplan & GTM readiness

_2026-06-14. Verified by a 5-domain readiness sweep (code + live prod probes). Strategy: validate the full monetized flow on **testnet + Stripe sandbox**, then cut to mainnet + Stripe live._

## Verdict

CONDITIONAL GO — one hard blocker must ship first, then it's a config-only launch. The product itself is sound: the Stripe billing stack (51 passing tests, raw-body webhook with pre-claim idempotent dedupe + 500-on-failure retries, past_due grace, kill-switch) is architecturally complete and live-confirmed safe in its current pre-flip state (checkout 409 BILLING_DISABLED, portal 503 STRIPE_NOT_CONFIGURED, webhook 400 MISSING_SIGNATURE). Smart-goal circles are fully wired end-to-end with NO 'coming soon' in current source or the deployed bundle (that was a stale cached deploy). zkLogin sessions are Postgres-backed/durable, there is genuinely no gas sponsorship, the Enoki key is server-only, and the critical fund-access hard invariant HOLDS: I verified only assertCanCreateCircle (zkLogin.ts:1294) and assertWithinMemberLimit (zkLogin.ts:5339) consult entitlements — all eight fund-flow handlers (contributeToCycleEscrow, claimPayout/adminTriggerPayout, withdrawWalletFunds, returnSecurityDeposit, paySecurityDeposit, executeRecovery, triggerAutoRelease) never touch the gate, so money is never paywalled. BUT a brand-new user literally cannot onboard today: GET /api/legal/doc?doc={risk,terms,privacy} returns a deterministic 500 (DOC_LOAD_FAILED) on production for all three docs because next.config.js has no outputFileTracingIncludes to bundle docs/legal-drafts/*.md into the serverless lambda (.vercelignore only fixes the BUILD-time SSG read, which is why /legal/* pages return 200 while the API 500s). With the risk modal unable to load, the scroll-gate checkbox stays permanently locked and the legal gate blocks the post-login /dashboard landing for every new user. Fix that one ENG item, flip on Stripe sandbox + Transak XAF sandbox, add error tracking, and this is a clean soft launch on testnet.

## Day-1 monitoring

- Onboarding completion: watch /api/legal/doc stays 200 (the regression that blocked everyone) and that new users actually clear the legal modal → reach /dashboard. Any spike in legal-doc 500s = re-broken tracing.
- Sentry: server API 500s (especially /api/zkLogin fund cases, /api/legal/*, /api/billing/webhook) and client crashes. This is your only real-time crash signal — watch the first hours closely.
- Stripe (TEST dashboard): checkout success rate, webhook delivery status (all 200s — any 4xx/5xx means signature/secret mismatch or processing failure triggering retries), subscription rows upserting to premium, and past_due events firing dunning correctly.
- Crons (Vercel logs): /api/cron/cycle-finalized + /api/cron/whatsapp-circle-events every minute, walrus-renewal daily 03:00. Watch for halted/missing_credentials states (WhatsApp creds) or lease/cursor stalls; confirm cursors advance and don't replay. External uptime monitor hits /api/health every 5 min.
- RPC rate-limits: the uncached /api/circle-stats fan-out + free public fullnode failover (blockvision/publicnode) can hit cooldowns under a homepage spike. Watch RPC errors/latency in logs and 'Insufficient gas'/failed reads in Sentry; if reads degrade, ship the circle-stats cache and consider a paid RPC key.
- Neon DB: connection-count / pool-exhaustion errors (confirm POOLED string in use) and /api/health db.latencyMs (~83-95ms now; a climb signals pool pressure).
- Faucet funding success: how many new users actually get test SUI vs stall at 0 balance (the top drop-off). High stall rate = drip needs attention.
- Conversion funnel: free→premium upgrade attempts, 402 UPGRADE_REQUIRED hits (gate firing), and BillingUpsellModal → /pricing → checkout completion rate. Caps are soft/bypassable, so funnel UX (not enforcement) drives revenue.
- WhatsApp (if creds set): keep WHATSAPP_TEMPLATES_ENABLED=false; watch for Meta 131047 (freeform outside 24h window) on lifecycle sends and confirm the 'your turn' nudge delivers. Watch /api/whatsapp/webhook for inbound verify health.
- Money-in: Transak sandbox session-creation success + partner dashboard for XAF/Cameroon errors; confirm /api/onramp/geo shows transak:true for CEMAC and the picker renders providers (not the empty 'fund from another exchange' state).
